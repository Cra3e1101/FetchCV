# Claude 审查意见采纳记录（2026-07-28）

本记录用于区分“值得进入产品的能力”与“看起来合理但会误导用户或破坏现有架构的建议”。

| 建议 | 决策 | FetchCV 的实现方式 |
| --- | --- | --- |
| ATS 评分 | 有条件采纳 | 提供确定性的“ATS 文本覆盖/就绪度”：硬要求、关键词、文档结构分别给出命中证据和缺口。明确声明它不是第三方 ATS 通过概率。 |
| 求职信 | 采纳 | 作为 ToolGateway 中的草稿写入工具；每段绑定已确认 `fact_id`，JD 引文必须能回溯到原文，数字和日期继续经过事实校验。 |
| DOCX 导出 | 采纳 | 新增独立的 ATS Word：单栏、自然阅读顺序、无表格/文本框/浮动图标。原模板 PDF 仍是正式版，不被替换。 |
| 面试来源多样化 | 部分采纳 | 保留“小红书优先、其他公开来源补充、用户材料可导入”的证据分层。不会把 LinkedIn 写死为稳定来源，也不会绕过登录或平台访问控制。 |
| 全量 TypeScript 迁移 | 暂不采纳 | 现阶段全量迁移会扩大回归面。后续从 API DTO、Agent Event、Tool Result 三个跨进程边界增量类型化。 |
| 批量岗位评估 | 延后 | 有价值，但优先级低于单岗位结果可信度和导出闭环。未来应复用同一基准简历、并行只读评估，不复制 Agent Loop。 |
| 编辑器 Undo/Redo | 已存在 | 嵌入式简历编辑器已经具备历史栈、撤销/重做按钮及 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Y`，不重复建设。 |
| 移除专用天气工具 | 采纳 | 通用 Agent 能力不等于为每个领域硬编码工具。天气等实时问题由模型自主组合 `search_web` 与 `read_web_page`，并基于实际来源回答。 |

## 产品原则

1. 不把不可验证的模型判断包装成“通过率”。
2. 正式 PDF 保持原模板视觉连续性；ATS Word 是额外投递格式。
3. 生成型投递材料必须绑定事实和来源，默认是待人工审阅草稿。
4. 新能力进入统一 Agent Loop、ToolGateway、权限与真实事件记录，不创建旁路服务。
