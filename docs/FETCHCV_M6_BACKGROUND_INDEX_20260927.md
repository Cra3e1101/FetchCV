# M6 按需后台索引增量（2026-09-27）

基于 208fee0，补齐原方案 §9、§22 的索引调度部分。首次检索或来源解析版本变化时，APP 和 Agent 使用同一异步构建入口。

- 按 Block ID 游标每次读取一个正文块，每批最多推进 64 个扫描步骤；空白片段和空 Block 也消耗步骤。批次之间让出事件循环，没有跨 await 的 SQLite 事务。
- 同一数据库的并发检索共用一次构建；单个调用者取消仅停止它的等待，不取消其他调用者的共享构建。关闭工作区中止构建。
- 派生 generation 完成且来源解析 revision 未变时，在最后一批事务中同时写 ready 与 SearchHead。来源中途更新返回 index_source_changed，不发布过期索引；不自动无限重试。
- 部分代保留且不作为 Head，旧完整代保留。不删除缓存或原始资料；不是跨重启续建功能，下次请求重新构建。
- 搜索先等待之前的写队列，但不占用之后的普通请求队列；返回前重新检查 scope 和来源权限。关闭先停止构建，再等待搜索、Agent 和解析任务结束。
- 同步检索接口仍供现有离线兼容调用；生产 APP RPC 与 Agent 工具已接异步入口。

## 范围与限制

这是按需增量调度，不承诺固定 200 ms 响应，也未以规模基准证明吞吐提升。单个 Block 的代码点数组仍在内存中；FTS 排名查询仍同步。正式分层/密封检索评测和 personal_fact 的 KnowledgeItem 引用尚未完成，因此 M5–M8 仍未全部验收。

上一候选包 m58-package-05 对应 208fee0，不包含本增量；不能把它的成功冒充本增量 packaged 验证。后续需重建候选包。回退可用本增量前源码；本增量未改领域表结构，未切换旧库、旧 Python 环境或旧 installer。
