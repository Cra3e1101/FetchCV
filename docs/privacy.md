# 数据与隐私

FetchCV 采用本地优先设计：工作区和业务资料保存在本机，模型调用与网页研究按功能需要连接外部服务。

## 数据如何使用

| 数据或操作 | 处理方式 |
| --- | --- |
| 简历、岗位、版本与本地知识 | 保存在本地业务数据库及工作区文件中。 |
| 模型 API Key | 通过 Electron `safeStorage` 和 Windows DPAPI 加密保存，由主进程使用。 |
| AI 对话与改写 | 按任务上下文将相关对话和材料文本发送至用户配置的模型服务。 |
| AI 增强导入 | 默认关闭；先本地解析，再展示实际脱敏文本，确认后外发。 |
| 网页与面经研究 | 向搜索服务和来源网站发起请求，并保存来源链接与相关证据。 |
| Skill、MCP 与可选服务 | 按配置和授权执行，外部服务可能接触对应工具输入。 |

普通模型对话不等同于增强导入的逐次确认流程。模型请求具有脱敏处理，但用户仍应核对待用材料，并了解所选服务的数据保留政策。不要将真实密钥或无关个人信息粘贴进对话。

## 本地存储

安装版使用 Electron 用户数据目录；开发模式默认使用独立资料目录。单独运行后端时，默认数据库为 `backend/data/fetchcv.db`。

API Key 的加密保护不代表整个资料库加密。备份或共享工作区时，应同时考虑数据库、导入文件、导出文件和日志中的内容。关闭应用后再备份，避免复制仍在写入的数据。

## 执行权限

- Sidecar 绑定本机回环地址，桌面进程使用控制令牌访问。
- 改写提案提供人工审阅入口，工具写入受到作用域与版本约束。
- 新 Skill 默认停用，内容变化后需要重新信任。
- MCP 工具逐项授权；写入需要目标范围和相应审批。
- 网页工具限制私网地址与危险请求，遇到站点访问限制不会绕过平台控制。

这些机制属于应用边界。启用扩展前，仍需了解其来源和行为；本地扩展程序不因接入 FetchCV 就自动获得操作系统沙箱。

## 提交反馈

请使用虚构或脱敏示例复现问题，遮盖姓名、电话、邮箱、公司内部资料和模型凭据。不要把原始简历、工作区数据库或完整浏览器会话上传到公开 Issue。
