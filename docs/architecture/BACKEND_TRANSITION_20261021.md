# 后端过渡边界（2026-10-21）

状态：本轮修复采用的过渡原则；不是永久放弃 V2，也不授权迁移用户数据。

## 当前事实

Electron 的 `FETCHCV_V2_STORAGE_ROOT` 开关选择两套互斥实现，默认启动 Python sidecar。
二者共用 `FetchCVAgentHost`，尚未达到完整业务能力对等。

| 能力 | Python sidecar | JS/V2 |
| --- | --- | --- |
| Pi 模型循环 | 共用 Electron 宿主 | 共用 Electron 宿主 |
| 桌面默认入口 | 默认 | 显式环境开关 |
| 简历领域任务、事实审批、公开面经调研 | 已有业务工具与门禁 | 不应假定有同等能力 |
| 文档分页、引用、检索与记忆 | 现有独立实现，长工具结果回读不足 | 已有实现，适合作为迁移目标的参考 |
| MCP／Skill | 独立实现 | 独立实现，需契约对齐 |
| 数据模型 | SQLAlchemy／SQLite | JS 存储 worker |

本表是源码能力边界，不代表以上功能均完成端到端验收。

## 本轮决策

1. 本轮修复以当前默认 Python 后端为生产兼容基线，运行时与协议修复放在共用 Electron 层。
2. 不自动切换默认后端，不迁移或删除用户数据，不删除旧模块。
3. V2 保留已有能力和测试。新增重复业务实现前，必须先声明迁移落点、旧入口的退役条件和回滚方式。
4. 工具响应可附带 `tools`，表示下一模型轮次应使用的完整清单；空数组表示无可用工具。缺少该字段时兼容旧后端，通过现有 `task-tools` 端点刷新。
5. 刷新失败时停止当前模型循环，不用旧清单继续推理，也不自动重试已完成的副作用。
6. 业务状态、审批、执行记录的权威仍在后端；宿主缓存仅供当前模型请求使用。

## 收敛前置条件

- 按业务链路比较简历、面经、独立聊天、MCP、Skill 的输入／输出／权限／恢复语义。
- 确定数据迁移映射，使用副本验证行数、引用、版本和审批记录可回查。
- 共用宿主契约测试在两个后端适配器上通过。
- 新后端具备现有业务入口及故障恢复，安装包数据迁移与回滚经过验证。

未完成这些条件前，不因目录名叫 V2 就把它当作默认生产后端。
