# 客户端交互审计

本轮按真实用户任务而不是后端模块划分交互。原则：用户只提供业务信息并做关键决定；状态机、事实权限和发布门禁留在系统内部。

| 场景 | 原问题 | 修正目标 |
|---|---|---|
| 首次使用 | 先出现岗位或“事实锁”，没有个人资料准备路径 | 先导入 PDF 简历并预览解析结果，再建立资料库 |
| 旧数据迁移 | JSON 迁移被包装成“导入简历” | PDF 是主入口；JSON 明确标记为旧版工作区迁移 |
| 资料库 | 只能在空状态导入，之后找不到入口 | 左栏提供常驻“个人资料库”，可查看基础简历和经历 |
| 新建岗位 | 没有候选人时仍可点击，表单无法提交 | 资料未就绪时引导先导入；就绪后才进入岗位表单 |
| JD | 旧岗位无 JD 时只能另建；已有 JD 不能修改 | 支持补充、编辑、保存 JD，并明确下一步 |
| Agent 运行 | 只有静态时间线，不能取消，用户不知道系统在做什么 | 显示当前动作、已完成动作、可取消和清晰等待反馈 |
| 经历匹配 | 用户被要求预先确认所有事实 | JD 分析后只确认本岗位相关经历；推荐与其他经历分层 |
| 改写审批 | 中低风险默认接受，容易误操作 | 所有建议默认“待决定”，逐条接受、保留原文或编辑后接受 |
| 错误恢复 | 直接显示内部 JSON；重试没有上下文建议 | 翻译错误、说明原因、提供与错误相匹配的修复入口 |
| 资产生成 | PDF、作品集按钮分散，用户必须猜顺序 | 一个“生成投递材料”动作按正确顺序完成并展示进度 |
| 发布与冻结 | 冻结动作缺少不可逆确认 | 二次确认绑定的岗位和资产版本，再冻结投递记录 |
| 反馈 | 全局 busy、无成功反馈、错误不可关闭 | 动作级加载、可关闭通知、成功结果与下一步提示 |
| 空状态 | 搜索无结果与完全无数据使用相同文案 | 区分无资料、无岗位、无搜索结果、无匹配经历 |
| 可访问性 | 自制弹窗缺少语义和键盘行为 | 弹窗支持 Escape、焦点可见、减少动画偏好 |

## 目标主流程

```text
导入 PDF 简历
→ 预览姓名、联系方式、章节与经历条目
→ 用户确认入库
→ 打开个人资料库
→ 新建岗位并输入 JD
→ Agent 分析 JD
→ 推荐相关经历并请求确认
→ 生成逐条改写建议
→ 用户逐条决定
→ 自动校验
→ 一键生成 PDF 与作品集
→ 用户最终确认并冻结投递版本
```
